title: Chain registry
description: Every CCTP V2 chain Whisk supports, with its domain, contracts, USDC address and capabilities, and the lookups over them.

The registry is a typed table of every chain CCTP V2 serves on EVM, Solana, Stellar and Starknet, mainnet and testnet. Builders and Iris calls take entries from it.

```ts
import {
  getChain,
  chainByEvmChainId,
  chainByDomain,
  chainsByNetwork,
  isChainId,
  attestationSeconds,
} from "@usewhisk/cctp";

const base = getChain("Base_Sepolia");
console.log(base.cctpDomain, base.usdc, base.capabilities.fastSource);

const fromWallet = chainByEvmChainId(84_532);
const fromIris = chainByDomain(6, "testnet");
const testnets = chainsByNetwork("testnet");

const input: string = "Arc_Testnet";
if (isChainId(input)) {
  const { min, max } = attestationSeconds(getChain(input), "standard");
  console.log(min, max);
}
```

The registry is also published on its own as `@usewhisk/cctp/chains`, and `@usewhisk/core` and `@usewhisk/react` re-export it.

## Lookups

| Function                                          | Returns                 | When nothing matches       |
| ------------------------------------------------- | ----------------------- | -------------------------- |
| `getChain(id: ChainId)`                           | `CctpChain`             | throws `UnknownChainError` |
| `chainByEvmChainId(evmChainId: number)`           | `EvmChain`              | throws `UnknownChainError` |
| `tryChainByEvmChainId(evmChainId: number)`        | `EvmChain \| undefined` | `undefined`                |
| `chainByDomain(domain: number, network: Network)` | `CctpChain`             | throws `UnknownChainError` |
| `chainsByNetwork(network: Network)`               | `readonly CctpChain[]`  | empty array                |
| `isChainId(value: string)`                        | `value is ChainId`      | `false`                    |

`ChainId` is the union of every `id` string in `CHAINS` (`"Ethereum"`, `"Base_Sepolia"`, `"Solana_Devnet"` and so on), so `getChain("Base_Sepoila")` fails to compile. Use `isChainId` to narrow a string from user input or a URL first.

Mainnet and testnet share a CCTP domain (Base and Base Sepolia are both domain 6), so `chainByDomain` needs the network. Iris tells the two apart by host, not by domain. Use `tryChainByEvmChainId` for a wallet's current chain, which can be any chain the wallet knows.

`UnknownChainError` extends `InvalidInputError` with code `invalid_chain`.

### Type guards and explorer links

```ts
import {
  getChain,
  isEvmChain,
  tryChainByEvmChainId,
  explorerTxUrl,
  explorerAddressUrl,
  UnknownChainError,
  chainByDomain,
} from "@usewhisk/cctp";

const supported = tryChainByEvmChainId(walletChainId);
if (!supported) console.log("Switch to a CCTP chain");

const devnet = getChain("Solana_Devnet");
console.log(explorerTxUrl(devnet, "5Uf...sig"));
console.log(
  explorerAddressUrl(
    getChain("Stellar"),
    "CBZL2IH7F6BIDAA3WBNXYKIXSATJGMSW7K5P5MJ6STX5RXN47TZJDF5T",
  ),
);

const arc = getChain("Arc");
if (isEvmChain(arc)) console.log(arc.evmChainId);

try {
  chainByDomain(4, "mainnet");
} catch (err) {
  if (err instanceof UnknownChainError) console.log(err.code);
}
```

`isEvmChain`, `isSolanaChain`, `isStellarChain` and `isStarknetChain` narrow a `CctpChain` to its ecosystem type. Switching on `chain.ecosystem` does the same.

`explorerTxUrl(chain, txHash)` and `explorerAddressUrl(chain, address)` build links on the chain's explorer and append `explorerQuery` (Solana Devnet's `?cluster=devnet`). Address links use `/contract/` on Starknet, `/contract/` or `/account/` on Stellar depending on the strkey, and `/address/` elsewhere.

## The `CctpChain` shape

`CctpChain` is a union of four types, told apart by `ecosystem`. Every entry is `as const`, so `Base.cctpDomain` has the literal type `6`.

```ts
import { getChain, type CctpChain } from "@usewhisk/cctp";

function describe(chain: CctpChain): string {
  switch (chain.ecosystem) {
    case "evm":
      return `EVM chain ${chain.evmChainId}, TokenMessengerV2 ${chain.tokenMessenger}`;
    case "solana":
      return `Solana ${chain.cluster}, program ${chain.tokenMessengerMinter}`;
    case "stellar":
      return `Stellar ${chain.stellarNetwork}, forwarder ${chain.cctpForwarder}`;
    case "starknet":
      return `Starknet ${chain.starknetNetwork}, chain id ${chain.chainId}`;
  }
}

console.log(describe(getChain("Stellar_Testnet")));
```

### Fields on every chain

<ResponseField name="id" type="ChainId">
  Stable string id, such as `"Arc"` or `"Base_Sepolia"`. These are the same ids
  Whisk 0.1 used.
</ResponseField>
<ResponseField name="label" type="string">
  Display name, such as `"OP Mainnet"`.
</ResponseField>
<ResponseField
  name="ecosystem"
  type='"evm" | "solana" | "stellar" | "starknet"'
>
  The discriminant (`Ecosystem`).
</ResponseField>
<ResponseField name="network" type='"mainnet" | "testnet"'>
  The `Network`. Pass it to every Iris call for a transfer from this chain.
</ResponseField>
<ResponseField name="cctpDomain" type="number">
  Circle's domain id (`CctpDomain`). Shared by a mainnet and its testnet.
</ResponseField>
<ResponseField name="usdcDecimals" type="6 | 7">
  `7` on Stellar, `6` everywhere else.
</ResponseField>
<ResponseField
  name="nativeCurrency"
  type="{ symbol: string; decimals: number }"
>
  The gas token. On Arc it is USDC with 18 decimals.
</ResponseField>
<ResponseField name="defaultRpcUrls" type="readonly string[]">
  Public RPCs, tried in order by the [RPC
  helpers](/reference/cctp/builders#reading-chain-state). Use your own in
  production.
</ResponseField>
<ResponseField name="explorerUrl" type="string">
  Explorer base URL, without a trailing slash.
</ResponseField>
<ResponseField name="explorerQuery" type="string">
  Optional. Appended to explorer links for explorers that serve several
  networks.
</ResponseField>
<ResponseField name="capabilities" type="ChainCapabilities">
  What Circle offers on this chain. See [Capabilities](#capabilities).
</ResponseField>

### `EvmChain`

| Field                    | Type                | Notes                                                                               |
| ------------------------ | ------------------- | ----------------------------------------------------------------------------------- |
| `evmChainId`             | `number`            | The EIP-155 chain id (`EvmChainId`).                                                |
| `usdc`                   | `` `0x${string}` `` | USDC ERC-20 address (`Address`).                                                    |
| `tokenMessenger`         | `Address`           | `TokenMessengerV2`. One address on every testnet, and on every mainnet except EDGE. |
| `messageTransmitter`     | `Address`           | `MessageTransmitterV2`. Same rule.                                                  |
| `tokenMessengerWithFees` | `Address`           | Optional. Present exactly when `capabilities.upfrontFeeSource` is true.             |

### `SolanaChain`

| Field                  | Type                         | Notes                                                                                            |
| ---------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------ |
| `cluster`              | `"mainnet-beta" \| "devnet"` | `SolanaCluster`.                                                                                 |
| `usdc`                 | `string`                     | USDC SPL mint, base58 (`SolanaPubkey`).                                                          |
| `tokenMessengerMinter` | `SolanaPubkey`               | `TokenMessengerMinterV2` program. Solana merges TokenMessenger and TokenMinter into one program. |
| `messageTransmitter`   | `SolanaPubkey`               | `MessageTransmitterV2` program.                                                                  |

The program ids are the same on mainnet-beta and devnet; only the USDC mint differs.

### `StellarChain`

| Field                  | Type                    | Notes                                                                               |
| ---------------------- | ----------------------- | ----------------------------------------------------------------------------------- |
| `stellarNetwork`       | `"public" \| "testnet"` | `StellarNetwork`.                                                                   |
| `networkPassphrase`    | `string`                | Needed to sign Soroban transactions.                                                |
| `usdcIssuer`           | `string`                | Circle's USDC issuer account, a G strkey (`StellarStrkey`).                         |
| `usdc`                 | `StellarStrkey`         | The USDC Stellar Asset Contract (C strkey), derived from the issuer and passphrase. |
| `tokenMessengerMinter` | `StellarStrkey`         | Burn contract.                                                                      |
| `messageTransmitter`   | `StellarStrkey`         | Receive contract.                                                                   |
| `cctpForwarder`        | `StellarStrkey`         | Circle's `CctpForwarder` contract.                                                  |

<Warning>
  A burn to Stellar must name `cctpForwarder` as both `mintRecipient` and
  `destinationCaller`, with the real recipient in the hook data. A user account
  as `mintRecipient` loses the funds for good. See [burns to
  Stellar](/reference/cctp/builders#burns-to-stellar).
</Warning>

### `StarknetChain`

| Field                  | Type                     | Notes                                                                                            |
| ---------------------- | ------------------------ | ------------------------------------------------------------------------------------------------ |
| `starknetNetwork`      | `"mainnet" \| "sepolia"` | `StarknetNetwork`.                                                                               |
| `chainId`              | `` `0x${string}` ``      | `SN_MAIN` or `SN_SEPOLIA` as a shortstring felt (`StarknetFelt`). Wallets check it when signing. |
| `usdc`                 | `StarknetFelt`           | USDC contract.                                                                                   |
| `tokenMessengerMinter` | `StarknetFelt`           | Burn contract.                                                                                   |
| `messageTransmitter`   | `StarknetFelt`           | Receive contract.                                                                                |

## Capabilities

`ChainCapabilities` comes from Circle's CCTP tables, per chain. Mainnet and testnet can differ.

<ResponseField name="fastSource" type="boolean">
  Circle offers Fast Transfer for burns from this chain. On the others, Standard
  (hard finality) is the only option, and `buildBurnIntent` refuses a Fast fee
  tier with `ProtocolError("no_route")`.
</ResponseField>
<ResponseField name="forwardingDestination" type="boolean">
  Circle's Forwarding Service can mint on this chain. When it is false, burn
  with `withForwarder: false` and submit the mint yourself.
</ResponseField>
<ResponseField name="upfrontFeeSource" type="boolean">
  Iris quotes an upfront fee for burns from this chain, paid through
  `TokenMessengerWithFees`. See
  [`buildBurnWithFeesIntent`](/reference/cctp/builders#buildburnwithfeesintent).
</ResponseField>
<ResponseField name="standardFeeSwitch" type="boolean">
  `TokenMessengerV2` has `getMinFeeAmount`, which can make a Standard burn cost
  more than Iris says. Read it with
  [`getStandardMinFee`](/reference/cctp/fees#getstandardminfee). On the other
  chains the call reverts.
</ResponseField>

## Attestation times

`attestationSeconds(chain, speed)` returns Circle's published average time to attest a burn from `chain`, as a `SecondsRange` (`{ min, max }`, in seconds). `speed` is `"fast"` or `"standard"` (`TransferSpeed`). The mint comes after the attestation, so the payer waits a little longer than this.

Circle publishes mainnet figures only; testnets share the domain and use the same numbers. Asking for `"fast"` on a chain without Fast throws `ProtocolError("no_route")`.
