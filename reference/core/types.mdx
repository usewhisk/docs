Everything here is exported from `@usewhisk/core`. Types without runtime code are also on `@usewhisk/core/types`, together with `DEFAULT_TOKEN`, `DEFAULT_FEE_BEARER`, `isBridgeRoute` and `isSendRoute`, so a type-only import pulls in nothing else.

```ts summary.ts
import type { Quote, SendResult, Step } from "@usewhisk/core";
import { formatUsdcAmount, isBridgeRoute } from "@usewhisk/core";

export function summary(quote: Quote): string {
  const route = isBridgeRoute(quote.route)
    ? `${quote.route.sourceChain} to ${quote.route.destinationChain}`
    : quote.route.chain;
  return `${route}: you pay ${quote.amountIn}, recipient gets ${formatUsdcAmount(quote.subunits.amountOut)} ${quote.token}`;
}

export function lastTx(result: SendResult): string | undefined {
  const done: Step[] = result.steps.filter((s) => s.state === "success");
  return result.kind === "success" ? result.finalTxHash : done.at(-1)?.txHash;
}
```

## Amounts

USDC amounts are decimal strings at the API edge and `bigint` subunits inside, with 6 decimals. Stellar's 7-decimal balances are scaled at the edge. See [Amounts and units](/concepts/amounts-and-units).

```ts
import {
  formatUsdcAmount,
  parseUsdcAmount,
  USDC_DECIMALS,
} from "@usewhisk/core";

const subunits = parseUsdcAmount("12.3456789");
console.log(subunits, formatUsdcAmount(subunits), USDC_DECIMALS);
```

| Export             | Signature                      | Notes                                                                                                                                                                                              |
| ------------------ | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `USDC_DECIMALS`    | `6`                            | The decimals CCTP messages carry.                                                                                                                                                                  |
| `parseUsdcAmount`  | `(input: string) => bigint`    | Trims, then accepts digits with at most one dot. Digits past the sixth decimal are dropped, never rounded. Throws `ConfigError` for anything else, and for zero. `"12.3456789"` gives `12345678n`. |
| `formatUsdcAmount` | `(subunits: bigint) => string` | Strips trailing zeros: `1500000n` gives `"1.5"`. Throws `ConfigError` for negative input.                                                                                                          |

## Resolvers

Also exported from `@usewhisk/core/resolvers` (the functions) and `@usewhisk/core/types` (the types).

```ts resolver.ts
import { addressResolver, composeResolvers } from "@usewhisk/core/resolvers";
import type { Resolver } from "@usewhisk/core/types";

const handles: Resolver = {
  name: "handles",
  matches: (input) => input.startsWith("@"),
  resolve: async (input, { chain }) => {
    const res = await fetch(
      `https://api.example.com/handles/${input.slice(1)}`,
    );
    if (res.status === 404) return null;
    const { address } = (await res.json()) as { address: string };
    return { address, chain, displayName: input };
  },
};

export const resolver = composeResolvers([addressResolver, handles], {
  name: "app",
});
```

  <Expandable title="Resolver">
    <ResponseField name="name" type="string" required>
      Shown in `ResolverError` messages.
    </ResponseField>
    <ResponseField name="matches" type="(input: string) => boolean" required>
      Synchronous shape check. Only matching resolvers are asked to resolve.
    </ResponseField>
    <ResponseField
      name="resolve"
      type="(input: string, ctx: ResolverContext) => Promise<ResolvedRecipient | null>"
      required
    >
      Return `null` to let the next resolver try. Throw `ResolverError` on
      unexpected failure.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="ResolverContext" type="{ chain: Chain }">
  The destination chain the input should resolve on.
</ResponseField>

<ResponseField name="addressResolver" type="Resolver">
  Matches input shaped like an address of any ecosystem, and resolves it when it
  fits the destination chain's format. The engine's default resolver.
</ResponseField>

<ResponseField
  name="composeResolvers"
  type="(resolvers: ReadonlyArray<Resolver>, options?: { name?: string }) => Resolver"
>
  Tries each matching resolver in order and returns the first non-null result.
  An error that is not already a `ResolverError` is wrapped in one. Throws a
  plain `Error` when `resolvers` is empty. `name` defaults to `"composite"`.
</ResponseField>

| Export                | Signature                                                            | Notes                                                                                                                                                                   |
| --------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `decideRoute`         | `(sourceChain: Chain, destinationChain: Chain) => Route`             | Throws `ConfigError` when either is missing.                                                                                                                            |
| `planRoute`           | `(input: PlanRouteInput) => RoutePlan`                               | Throws `RouteUnavailableError` (`same_chain`, `source_adapter_required`, `destination_adapter_required`) and `NetworkMismatchError`. Does not apply the Fast allowance. |

```ts
import { connectedEcosystems, decideRoute, planRoute } from "@usewhisk/core";

const route = decideRoute("Solana_Devnet", "Arc_Testnet");
const plan = planRoute({
  source: "Solana_Devnet",
  destination: "Arc_Testnet",
  connected: connectedEcosystems({ kind: "solana" }),
  useForwarder: true,
});
console.log(
  route.kind,
  plan.speed,
  plan.mint,
  plan.requiredAdapters,
  plan.etaSeconds,
);
```

## Quote

What `engine.quote` returns. Amount strings are decimal USDC; `subunits` holds the same values as 6-decimal `bigint`s, and `send` signs those.

<ResponseField name="id" type="string">
  New for every quote, including a refreshed one. Bridges use it as the inflight
  record id.
</ResponseField>

<ResponseField name="issuedAt" type="number">
  Milliseconds since the epoch.
</ResponseField>

<ResponseField name="expiresAt" type="number">
  `issuedAt` plus 60 seconds. `send` throws `QuoteExpiredError` after it.
</ResponseField>

<ResponseField name="feeMode" type={'"maxFee" | "upfront"'}>
  `"maxFee"`: Circle takes its fee out of the burn, capped by `subunits.maxFee`.
  `"upfront"`: the payer pays Circle's signed fee beside the burn, at most
  `subunits.maxFee`, and the whole burn mints. Upfront is used only with
  `feeBearer: "sender"`, from EVM sources that support it, not into Stellar, and
  only when there is a Fast or forwarding fee to pay.
</ResponseField>

<ResponseField name="route" type="Route">
  Send or bridge, with the chains.
</ResponseField>

<ResponseField name="recipient" type="ResolvedRecipient">
  Who receives.
</ResponseField>

<ResponseField name="amountIn" type="string">
  The most debited from the payer, merchant fee included. Show it as "You pay".
</ResponseField>

<ResponseField name="amountOut" type="string">
  The least the recipient gets. Show it as "Recipient gets".
</ResponseField>

<ResponseField name="amountBurned" type="string">
  The amount burned on the source chain. Equal to the requested amount on a
  same-chain send.
</ResponseField>

<ResponseField name="token" type="Token">

</ResponseField>

<ResponseField name="fees" type="FeeBreakdown">

</ResponseField>

<ResponseField name="subunits" type="object">

    <ResponseField name="amountIn" type="bigint">

    </ResponseField>
    <ResponseField name="burnAmount" type="bigint">
      Burned on the source chain. `0n` on a same-chain send.
    </ResponseField>
    <ResponseField name="burnFee" type="bigint">
      Circle's protocol fee, before the Fast buffer.
    </ResponseField>
    <ResponseField name="forwarderFee" type="bigint">
      Circle's forwarding fee, `0n` when not forwarded.
    </ResponseField>
    <ResponseField name="maxFee" type="bigint">

    <ResponseField name="amountOut" type="bigint">
      The least the recipient gets.
    </ResponseField>
    <ResponseField name="customFee" type="bigint">
      The merchant fee, `0n` without a `feePolicy`.
    </ResponseField>
  </Expandable>
</ResponseField>

</ResponseField>

<ResponseField name="plan" type="RoutePlan">

</ResponseField>

  <Expandable title="CustomFeeOutcome">
    <ResponseField name="status" type={'"paid" | "unpaid"'} required>
      `paid` once every fee share landed, in the batch with the burn or after it.
    </ResponseField>
    <ResponseField name="amount" type="string" required>
      The whole fee, such as `"0.25"`.
    </ResponseField>
    <ResponseField name="txHashes" type="`0x${string}`[]">

    </ResponseField>

    </ResponseField>

</ResponseField>

```ts
import type { CustomFeeOutcome } from "@usewhisk/core";

export function describeFee(fee: CustomFeeOutcome | undefined): string {
  if (!fee) return "No merchant fee.";
  if (fee.status === "paid") return `Fee of ${fee.amount} USDC paid.`;
  return fee.error
    ? `Fee of ${fee.amount} USDC not paid: ${fee.error.message}`
    : `Fee of ${fee.amount} USDC not charged.`;
}
```

`CustomFeeOutcome` is exported from `@usewhisk/core` only. From `@usewhisk/react`, name it as `NonNullable<SendSuccess["customFee"]>`.

The parameter and option types of the engine methods (`QuoteParams`, `SendParams`, `SendListeners`, `SendStepListener`, `MaxSendable`, `ResumeOptions`, `ResumeFromTxParams`, `RefundParams`) are documented with their methods on [Engine](/reference/core/engine). `SendStepListener` is `(step: Step) => void`.

## Inflight records

```ts
import {
  createMemoryInflightStore,
  createStorageInflightStore,
  type InflightRecord,
  type InflightStore,
} from "@usewhisk/core";

const memory: InflightStore = createMemoryInflightStore();
const persistent: InflightStore = createStorageInflightStore(
  window.sessionStorage,
);

const pending: readonly InflightRecord[] = await persistent.list();
for (const record of pending) await memory.put(record);
```

<ResponseField name="InflightStore" type="interface">
  `put(record): Promise<void>`, `list(): Promise<readonly InflightRecord[]>`, `remove(id): Promise<void>`. The engine never removes a burned record by itself.
</ResponseField>

<ResponseField name="createMemoryInflightStore" type="() => InflightStore">
  The engine's default. Lasts as long as the engine.
</ResponseField>

<ResponseField name="createStorageInflightStore" type="(storage: InflightStorage) => InflightStore">
  Keeps each record as JSON under `whisk:inflight:<id>`. Lists only valid version 2 records, oldest first, and leaves other keys alone. `InflightStorage` is the `getItem`, `setItem`, `removeItem`, `key` and `length` part of the Web Storage API.
</ResponseField>

<ResponseField
  name="InflightStep"
  type={'"signing" | "burned" | "attested" | "minted"'}
>
  `signing` is written before the wallet is asked, `burned` when the burn hash
  comes back, `attested` after Circle signs, `minted` once the recipient has the
  USDC.
</ResponseField>

<ResponseField name="InflightRecord" type="object">
  JSON-safe. Amounts are subunit strings.

## Receipts

Derive a transfer's status from its hash without running the engine. `useReceipt` and `<WhiskReceipt>` are built on these.

```ts
import {
  deriveReceiptView,
  describeReceiptChains,
  RECEIPT_STAGE_HELP,
  RECEIPT_STAGE_LABELS,
  type ReceiptInput,
} from "@usewhisk/core";

const input: ReceiptInput = {
  sourceChain: "Base_Sepolia",
  sourceTxHash:
    "0x5f2c9a1e7b3d4c6f8a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f",
  destinationChain: "Arc_Testnet",
  irisStatus: "pending_confirmations",
};
const view = deriveReceiptView(input);
const { sourceLabel, destinationLabel } = describeReceiptChains(view, input);
console.log(
  `${sourceLabel} to ${destinationLabel}: ${RECEIPT_STAGE_LABELS[view.stage]}`,
  RECEIPT_STAGE_HELP[view.stage],
);
```

<ResponseField name="ReceiptInput" type="object">
  `sourceChain`, `sourceTxHash`, `destinationChain` (equal to `sourceChain` for
  a send), `destinationTxHash?`, `irisStatus?` (`undefined` before the first
  Iris response), `hasError?` (forces `failed`).
</ResponseField>

<ResponseField
  name="ReceiptStage"
  type={
    '"submitted" | "awaiting_attestation" | "attested" | "settled" | "failed"'
  }
>
  `submitted`: Iris has not seen the burn. `awaiting_attestation`: Iris waits
  for source confirmations. `attested`: attestation ready, no mint hash known.
  `settled`: a mint hash is known, or it was a same-chain send. `failed`:
  `hasError` was set.
</ResponseField>

<ResponseField name="ReceiptView" type="object">
  `{ stage, steps, isCrossChain, sourceExplorerUrl, destinationExplorerUrl? }`. `steps` is a single `transfer` for a send, otherwise `burn`, `fetchAttestation`, `mint`.
</ResponseField>

| Export                  | Signature                                                                                     | Notes                                                   |
| ----------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| `deriveReceiptView`     | `(input: ReceiptInput) => ReceiptView`                                                        | Pure. Call again with a fresher `irisStatus`.           |
| `describeReceiptChains` | `(view: ReceiptView, input: ReceiptInput) => { sourceLabel; destinationLabel; isCrossChain }` | Chain labels for display.                               |
| `RECEIPT_STAGE_LABELS`  | `Record<ReceiptStage, string>`                                                                | English labels, such as `"Confirming on source chain"`. |
| `RECEIPT_STAGE_HELP`    | `Record<ReceiptStage, string>`                                                                | One English sentence per stage.                         |

## Iris

A small wrapper over Circle's Iris attestation API. For the full client see [CCTP Iris](/reference/cctp/iris).

```ts attestation.ts
import {
  buildReceiveMessageCall,
  fetchAttestationOnce,
  getIrisBaseUrl,
  IRIS_SANDBOX_URL,
  pollAttestation,
} from "@usewhisk/core";

const burnTx =
  "0x5f2c9a1e7b3d4c6f8a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d1e2f";

const once = await fetchAttestationOnce("Base_Sepolia", burnTx);
const done = await pollAttestation("Base_Sepolia", burnTx, {
  timeout: 5 * 60_000,
  pollingInterval: 5_000,
  onUpdate: (m) => console.log(m.status),
});

if (done.status === "complete" && done.message && done.attestation) {
  const call = buildReceiveMessageCall(
    "Arc_Testnet",
    done.message,
    done.attestation,
  );
  console.log(call?.address, call?.functionName, call?.args);
}
console.log(once.status, getIrisBaseUrl("Base_Sepolia") === IRIS_SANDBOX_URL);
```

<ResponseField

  type={'"pending_confirmations" | "complete" | "not_found"'}

  `not_found` until Iris has seen the burn.
</ResponseField>

<ResponseField

  type="{ status: IrisStatus; message?: string; attestation?: string; eventNonce?: string }"
>
  `message` and `attestation` are `0x` hex, present once complete.
</ResponseField>

<ResponseField

>
  `baseUrl` defaults to the Iris host for the source chain's network.
</ResponseField>

<ResponseField
  name="PollAttestationOptions"
  type="FetchAttestationOptions & { timeout?: number; pollingInterval?: number; onUpdate?: (msg: IrisMessage) => void }"

</ResponseField>

| Export                 | Signature                                                                                             | Notes                                                                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fetchAttestationOnce` | `(sourceChain: Chain, burnTxHash: string, options?: FetchAttestationOptions) => Promise<IrisMessage>` | One lookup. Throws `@usewhisk/cctp` Iris errors.                                                                                                                  |
| `pollAttestation`      | `(sourceChain: Chain, burnTxHash: string, options?: PollAttestationOptions) => Promise<IrisMessage>`  | Polls until `complete` or the timeout, then returns the latest status (it does not throw on timeout). Throws an `AbortError` `DOMException` when `signal` aborts. |

## Webhook signing

Server-side HMAC-SHA256 helpers for signing and verifying JSON payloads that your own servers send each other, such as a payment confirmation from your checkout backend. Whisk 0.3 does not send webhooks itself. They use Web Crypto, so they run on Node 18+, Deno, Bun and edge runtimes. Never ship the secret to a browser.

```ts webhook.ts
import { verifyWebhook, signWebhook } from "@usewhisk/core";

declare const secret: string;

const signed = await signWebhook({ orderId: "A-1001", status: "paid" }, secret);
await fetch("https://merchant.example.com/hooks/whisk", {
  method: "POST",
  headers: signed.headers,
  body: signed.body,
});

export async function handle(request: Request): Promise<Response> {
  const rawBody = await request.text();
  const verified = await verifyWebhook<{ orderId: string }>(
    rawBody,
    Object.fromEntries(request.headers),
    secret,
  );
  if (!verified.ok) return new Response(verified.reason, { status: 401 });
  return new Response(verified.payload.orderId);
}
```

| Export                           | Signature                                                                                                                                                           | Notes                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `signWebhook`                    | `<T>(payload: T, secret: string, options?: SignWebhookOptions) => Promise<SignWebhookResult>`                                                                       | Wraps the payload in a `WebhookEnvelope` and signs `` `${timestamp}.${body}` ``. Throws `ConfigError` for an empty secret or without Web Crypto.    |
| `verifyWebhook`                  | `<T>(rawBody: string, headers: Record<string, string \| string[] \| undefined>, secret: string, options?: VerifyWebhookOptions) => Promise<WebhookVerifyResult<T>>` | Pass the raw body before JSON parsing. Header lookup ignores case. Returns `{ ok: false, reason }` instead of throwing, except for an empty secret. |
| `WHISK_SIGNATURE_HEADER`         | `"x-whisk-signature"`                                                                                                                                               | Hex HMAC.                                                                                                                                           |
| `WHISK_TIMESTAMP_HEADER`         | `"x-whisk-timestamp"`                                                                                                                                               | Milliseconds since the epoch.                                                                                                                       |
| `WHISK_WEBHOOK_VERSION`          | `"v1"`                                                                                                                                                              |                                                                                                                                                     |
| `DEFAULT_TIMESTAMP_TOLERANCE_MS` | `300000`                                                                                                                                                            | Allowed clock skew (5 minutes).                                                                                                                     |
